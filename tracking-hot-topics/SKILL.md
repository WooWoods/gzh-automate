# 行业热点选题追踪

实时抓取全网平台热点事件，结合用户账号定位，自动生成高爆款潜力的选题方案。

## 触发条件

以下场景自动触发本 Skill：
1. 用户请求查看热点/热搜/热门话题
2. 用户请求选题推荐/选题策划/内容灵感
3. 用户请求分析某个话题的爆款潜力
4. 用户请求追踪特定赛道/领域的行业动态
5. 定时自动执行（通过 /loop 或 Schedule 设置）

## 执行流程总览

```
Phase 0: 配置加载与验证
    ↓
Phase 1: 多平台热点并行抓取（6 Agent Swarm）
    ↓
Phase 2: 热度趋势与情绪分析
    ↓
Phase 3: 选题匹配与生成（标题/大纲/建议）
    ↓
Phase 4: 爆款潜力评级（六维度评分）
    ↓
Phase 5: Markdown 报告生成
```

## Phase 0: 配置加载与验证

### 0.1 检查配置文件

MUST 首先检查用户工作目录下是否存在 `hot-topics-config.yaml` 配置文件。

**如果配置文件存在**：
- 读取并解析 YAML 配置
- 执行配置验证（见 `references/config-schema.md` 的验证规则）
- 验证通过 → 进入 Phase 1
- 验证失败 → 提示具体错误，使用默认值填充缺失字段

**如果配置文件不存在**：
- MUST 触发首次配置引导流程
- 引导分三轮进行（见 `references/config-schema.md` 的引导流程）：
  - 第一轮（必填）：账号名、主阵地平台、赛道
  - 第二轮（可选）：内容风格、粉丝画像、内容形式
  - 第三轮（可选）：过往爆款、竞品账号、回避话题
- 引导完成后生成配置文件并保存

### 0.2 配置验证规则

| 字段 | 必填 | 默认值 |
|------|------|--------|
| account.name | 是 | "我的账号" |
| account.platform | 是 | "未指定" |
| account.niche | 是 | "通用" |
| report_settings.max_topics | 否 | 10 |
| report_settings.min_viral_score | 否 | 70 |

## Phase 1: 多平台热点并行抓取

### 1.1 Agent 分工

MUST 启动 6 个并行 SubAgent（subagent_type: "Explore"），每个 Agent 负责不同平台组的热点抓取。

| Agent | 抓取目标 | 搜索策略 | 搜索预算 |
|-------|---------|---------|---------|
| Agent 1 | 微博热搜 + 抖音热点 | WebSearch: "{日期} 微博热搜榜 今日" + "{日期} 抖音热搜榜" | 2次 |
| Agent 2 | 小红书热门 + 公众号热点 | WebSearch: "{赛道} 小红书 热门话题 爆款" + "{赛道} 微信公众号 热门文章" | 2次 |
| Agent 3 | 知乎热榜 + 百度热搜 | WebSearch: "知乎热榜 今日" + "百度热搜榜 今日" | 2次 |
| Agent 4 | B站热门 + 头条热榜 | WebSearch: "B站热门视频 今日" + "今日头条 热榜" | 2次 |
| Agent 5 | 跨平台情绪分析 | WebSearch: "{TOP3热点话题} 用户评论 舆论 情绪" | 2次 |
| Agent 6 | 行业赛道深度追踪 | WebSearch: "{niche} 行业动态 最新趋势 2025" + "{niche} 热门事件" | 2次 |

### 1.2 每个 Agent 的硬性要求

- MUST 记录数据来源和抓取时间
- MUST 区分一手数据（平台接口/官方榜单）vs 二手数据（媒体报道/搜索结果）
- MUST 标注数据可信度：`high`（官方榜单）/ `medium`（媒体报道）/ `low`（间接推测）
- MUST 对每个话题提取：标题、热度值、来源平台、排名、链接
- 当某个平台数据获取失败时，MUST 标注"该平台数据获取失败"并继续其他平台，NEVER 阻断整体流程

### 1.3 数据标准化

所有 Agent 返回的数据 MUST 统一为以下格式：

```
- 话题标题
- 来源平台（中文名）
- 热度值/热度描述
- 排名
- 数据来源（api/web_search）
- 数据可信度（high/medium/low）
- 链接（如有）
```

### 1.4 降级策略

当 WebSearch 无法获取某平台数据时：
1. 尝试使用统一 API `https://60s.viki.moe/v2/{platform}`（通过 curl 获取）
2. 如果 API 也失败，在报告中标注该平台数据缺失
3. NEVER 因为单个平台失败而中断整个流程

## Phase 2: 热度趋势与情绪分析

### 2.1 跨平台话题聚合

- 识别出现在 2 个及以上平台的共性话题
- 按跨平台数量和总热度排序
- 输出 TOP 20 跨平台话题列表

### 2.2 趋势判断

对每个话题判断当前趋势阶段：

| 阶段 | 判断信号 | 创作策略 |
|------|---------|---------|
| 萌芽期 | 仅1-2个平台出现，讨论量少但增速快 | 抢首发，快速产出 |
| 爆发期 | 多平台同时出现，讨论量急速增长 | 立即创作，抢占流量红利 |
| 稳定期 | 热度高位但增速放缓 | 差异化角度切入 |
| 衰退期 | 热度持续下降 | 不建议投入 |

### 2.3 情绪倾向分析

对每个话题分析情绪倾向：

| 情绪类型 | 内容策略 |
|---------|---------|
| 好奇/求知 | 满足信息缺口，提供独家解读 |
| 焦虑/担忧 | 提供解决方案，缓解焦虑 |
| 愤怒/争议 | 理性分析，提供多元视角 |
| 喜悦/共鸣 | 放大情绪，引发转发 |
| 客观/中性 | 深度解读，提供增量信息 |

## Phase 3: 选题匹配与生成

### 3.1 赛道匹配筛选

基于配置文件中的 `account.niche`、`account.sub_niches`、`account.target_audience`，从所有热点话题中筛选出与账号赛道匹配的话题。

匹配规则：
- 完全匹配（话题直接命中赛道关键词）→ 优先推荐
- 部分匹配（话题与赛道细分方向相关）→ 次优推荐
- 间接相关（话题受众与粉丝画像重合）→ 可选推荐
- 命中回避话题（`content_preferences.avoid_topics`）→ MUST 排除

### 3.2 爆款标题生成

对每个推荐选题，MUST 生成 3 个不同风格的标题：

1. **数字+痛点型**：`[数字] + [痛点/收益] + [解决方案暗示]`
2. **悬念提问型**：`[反常识/意外事实] + ？`
3. **反常识型/对比型**：`[颠覆认知的结论]` 或 `[A vs B] + [结论]`

标题生成 MUST 遵循：
- 符合目标平台的标题字数限制（见 `references/content-strategies.md`）
- 与账号赛道高度相关
- NEVER 生成标题党（内容必须能兑现标题承诺）
- 标注每个标题使用的公式类型

### 3.3 结构化大纲生成

对每个推荐选题，生成结构化大纲：

```
- 开头（钩子策略）：{具体建议}
- 核心内容 1：{要点}
- 核心内容 2：{要点}
- 核心内容 3：{要点}
- 结尾（行动号召策略）：{具体建议}
```

大纲 MUST 根据话题类型选择合适的结构模板（见 `references/content-strategies.md`）：
- 干货教程型
- 观点输出型
- 对比测评型

### 3.4 创作建议生成

对每个推荐选题，MUST 输出以下创作建议：
- 推荐平台（基于配置的 `account.platform`）
- 推荐形式（基于配置的 `content_preferences.formats`）
- 发布时机（基于 `references/content-strategies.md` 的各平台最佳发布时间）
- 关键标签（3-5个相关标签）
- 注意事项（如敏感点、版权风险等）

### 3.5 竞品差异化分析

如果配置文件中包含 `competitors`，MUST 对每个选题进行竞品差异化分析：
- 竞品已覆盖的角度
- 建议切入的差异化角度
- 差异化创作建议

## Phase 4: 爆款潜力评级

### 4.1 六维度评分

对每个推荐选题执行六维度评分（详见 `references/scoring-model.md`）：

| 维度 | 权重 | 评估重点 |
|------|------|---------|
| 热度趋势 H | 25% | 搜索频率、跨平台覆盖、热度增速 |
| 赛道匹配 M | 25% | 关键词命中、粉丝画像契合、风格适配 |
| 竞争差异 D | 20% | 同类内容密度、差异化角度、竞品覆盖度 |
| 情绪激活 E | 15% | 情绪强度、共鸣广度、争议性 |
| 时效窗口 T | 10% | 生命周期阶段、剩余红利时间 |
| 互动潜力 I | 5% | 评论讨论空间、UGC 引发可能 |

### 4.2 综合评分公式

```
Total = H × 0.25 + M × 0.25 + D × 0.20 + E × 0.15 + T × 0.10 + I × 0.05
```

### 4.3 评级标准

| 总分 | 评级 | 建议动作 |
|------|------|---------|
| 90-100 | S 级 | 立即创作，抢占第一波流量 |
| 80-89 | A 级 | 今日内完成创作发布 |
| 70-79 | B 级 | 可纳入本周创作计划 |
| 60-69 | C 级 | 观察热度变化，备选 |
| <60 | D 级 | 不建议投入 |

### 4.4 过往爆款校准

如果配置文件中包含 `past_viral_content`，MUST 将当前评分与过往爆款进行对比：
- 计算当前话题与过往爆款的相似度
- 识别可复用的爆款模式
- 在报告中输出「历史对比与复盘」章节

## Phase 5: Markdown 报告生成

### 5.1 报告结构

MUST 按照以下结构生成完整报告（详见 `references/report-template.md`）：

1. **全网热点概览**：TOP 10 话题表 + 平台热度分布
2. **赛道相关热点筛选**：匹配度排序的话题列表
3. **重点选题方案**：每个选题包含评级 + 六维度评分 + 3个标题 + 大纲 + 建议 + 竞品差异化
4. **情绪与趋势分析**：情绪分布 + 走势预判
5. **历史对比与复盘**（可选）：与过往爆款的相似度分析

### 5.2 报告输出规则

- MUST 将报告保存为 Markdown 文件
- 文件命名：`hot-topics-report-{YYYY-MM-DD-HH-mm}.md`
- 保存路径：配置文件中 `report_settings.output_dir` 指定的目录（默认 `./hot-topics-reports/`）
- MUST 在对话中输出报告摘要（TOP 3 选题 + 评级）
- MUST 提供报告文件的完整路径供用户查看

### 5.3 报告质量检查

生成报告前 MUST 自检：
- [ ] 所有表格格式正确
- [ ] 评分计算无错误（加权之和 = 综合得分）
- [ ] 评级与分数区间匹配
- [ ] 标题与账号赛道相关
- [ ] 大纲结构完整（开头 + 核心内容 + 结尾）
- [ ] 创作建议具体可操作
- [ ] 选题数量不超过 `max_topics` 配置
- [ ] 仅包含 `min_viral_score` 以上的选题

## 定时执行指南

### 手动触发

用户直接对话即可触发：
```
> 帮我追踪今天的全网热点
> 最近有什么选题推荐
> 分析一下 AI 话题的爆款潜力
```

### 定时自动执行

用户可通过以下方式设置定时执行：

**方式 1：使用 /loop 命令**
```
/loop 2h 运行热点选题追踪Skill，生成最新报告
/loop 0 9 * * * 每天早上9点运行热点选题追踪
```

**方式 2：使用 Schedule 工具**
引导用户创建定时任务，cron 表达式示例：
- 每2小时：`0 */2 * * *`
- 每天早上9点：`0 9 * * *`
- 工作日早中晚：`0 9,12,18 * * 1-5`

### 报告自动管理

- 每次运行时对比上次报告，标注新增/升级/降级的话题
- 建议保留最近 7 天的报告

## 关键约束

1. MUST NEVER 编造不存在的话题或热度数据 — 所有数据必须来自实际搜索结果
2. MUST NEVER 忽略配置文件中的回避话题（`avoid_topics`）
3. MUST 在数据获取失败时优雅降级，NEVER 中断整个流程
4. MUST 控制每个 Agent 的搜索次数在 2-3 次以内
5. MUST 在报告中标注数据来源和可信度
6. MUST 为每个选题生成至少 3 个不同风格的标题
7. MUST 在报告末尾标注数据抓取时间和报告生成时间
